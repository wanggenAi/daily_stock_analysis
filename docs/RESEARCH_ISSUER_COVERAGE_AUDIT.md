# All-A issuer collection: bounded-coverage accounting

The 2026-09-26 source audit found that the genuine scheduled All-A artifact 10874605479 (market as-of Sep24) contained 41 noncached **industry** attempts but did not establish newly fetched, newly published official company disclosure. The live scheduled workflow uses `--evidence-queue-size 80`, `--fundamental-limit 30`, `--deep-review-size 30`; the current Deep invocation independently bounds `auto_evidence_limit=min(50,max(deep_review_size,active+10,...))`. These intentionally bounded stages do not constitute 80 issuer collection attempts. We must distinguish an attempted, cached, not-attempted or unverified row before interpreting 77/80 evidence failures as substantive company negatives.

This isolated addition exposes `issuer_collection_coverage` inside the existing All-A `run_summary.json` and reads the existing Deep `auto_evidence_audit.csv`. Counts report requested top-queue codes, explicit configured budgets, audited issuer codes, noncached issuer attempts, cached-only codes, not-audited codes and noncached OK original-URL codes. Missing audit is UNKNOWN/null, never zero. Noncached successful URL **never** proves a new immutable fingerprint, independently dated issuer period, evidence PASS or trade authority.

This PR does not increase collection budget, retry the consumed Deep/Terminal, create new workflows, relax gates or touch either V4 cursor or Canonical. Follow-up must use a genuinely new source period/fingerprint, decide separately on bounded 30/80 coverage strategy, and test collection/rate limits against actual official endpoints before increasing the research budget.
